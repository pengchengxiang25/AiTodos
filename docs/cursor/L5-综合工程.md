# L5 · 综合工程（端到端自动化）

知识点来源：《Cursor 方法论》方法9、《实践落地》项目4、学习地图 L5「CI 自动修复 bot」。
核心：组合前四层做出端到端产物——CI 质量门 + 失败自动修复开 PR。

## 产物

| 文件 | 作用 |
|---|---|
| `__tests__/todosSelectors.test.ts` | 状态层 selector 纯函数单测（CI 靶子）|
| `__tests__/todosUseCase.test.ts` | 领域层业务规则单测（mock service）|
| `.github/workflows/ci.yml` | 质量门：`yarn install --immutable` → eslint → tsc --noEmit → jest |
| `.github/workflows/cursor-autofix.yml` | CI 失败 → 云端 Agent 修复 → 自动开 PR |

## 端到端链路（五层如何串起来）

```
提交代码
  → CI(ci.yml) 跑 lint/tsc/jest        [L5]
  → 失败触发 cursor-autofix.yml         [L5]
    → 调 automation/auto-fix.mjs        [L3 SDK · 云端 autoCreatePR]
      → Agent 遵守 AGENTS.md + .cursor/rules 修复   [L2 Rules 约束]
      → 受 hooks 危险命令边界保护          [L2 Hooks 护栏]
  → 团队通过 plugin 获得同一套约束         [L4 分发]
```

## 关于类型检查（非阻塞）

CI 的 `tsc --noEmit` 目前设为 `continue-on-error`，因为项目存在**预置类型债**：

- `src/App.tsx` 动态 `import()` 需要 `module` 设为 `es2020+`（当前继承的配置为 commonjs）。
- `src/bundles/todos.entry.ts` 引用了尚未实现的 `../host/featureRegistry` 与 `injectReducer`（分包 host 侧未完成）。
- `src/presentation/components/LazyScreen.tsx` 泛型 props 赋值告警。

这些不在本次改造范围内。`lint` 与 `test` 是硬门；类型债逐步清零后把该步骤改回阻塞即可。

## 前置配置

- 在仓库 Secrets 配 `CURSOR_API_KEY`（建议 Service Account key）。
- 仓库需已连接 SCM（否则 `auto-fix.mjs` 抛 `IntegrationNotConnectedError`，读 `helpUrl` 重连）。

## 为什么先补测试

本项目原本无有效测试（唯一的 `App.test.tsx` 因 jest 未配置资源/ESM 转译，从未通过）。选 selector 与 domain 这两处**纯函数**作为首批靶子：最稳、最能反映业务规则、无需渲染环境，是 CI 与"自动修复"最合适的验证目标。

## 顺带修复的测试基建（jest.config.js）

- `moduleNameMapper`：图片资源映射为桩，避免 node_modules 里的 `.png` 被当 JS 解析。
- `transformIgnorePatterns`：允许转译 react-redux / redux-toolkit / navigation 等 ESM 依赖。
- Mirage 在测试中以空实现替代（依赖浏览器 `XMLHttpRequest`，node 环境不可用）。
- `testPathIgnorePatterns` 暂排除 `App.test.tsx`：全量渲染冒烟测试还需 `BackHandler`/原生模块 mock，属预置基建缺口，补齐后再启用。

检验：CI 失败后自动产出修复 PR，且危险操作被 hooks/sandbox 拦住。
